# 07 - 单人开发方案（Q2 已拍板）

> 日期：2026-11-06　状态：替代 `design/05-review-roadmap.md` 中“3 人全职”的人力假设与路线图；其余设计文档的产品目标不变。
> 输入：用户确认 **单人开发，以 Claude Code 等编程 Agent 辅助编码**。

## 1. 这个决定改变了什么

05 号路线图是按 3 名全职（2 个 Rust 加 1 个前端）排的，自建 Rust 内核在这个人力下可行。只有一个人时，最该省的不是写代码的时间（AI 能写），而是**长期维护、调试和集成的总量**。一个人加 AI 能写出内核，但维护不起“内核 + 3 个驱动 + 桌面壳 + 移动端 + 多机网络”这一整套自研栈。

因此推荐调整如下：

| 议题 | 原推荐（3 人） | 单人推荐 | 理由 |
|---|---|---|---|
| Q1 内核 | 自建 Rust 薄内核，DSH 作为 Plan B | **以 DeepSeek Harness（DSH）为底座，只写插件和 bundle，不 fork 主干** | 见 §2：DSH 已覆盖需求的大部分，缺口正好是我们的差异化 |
| Q7 桌面壳 | Tauri 2 + React | **v1 直接用 DSH 自带的 Electron 桌面端和 Web UI，通过 client inject 加自己的界面** | 放弃“轻量安装包”换取不维护壳；Tauri 重写放到有用户之后 |
| Q8 手机端 | PWA + Tailscale | **DSH Web UI + `tailscale serve`**（移动端布局可用性**未验证**，M0 内实测） | 不另写 PWA |
| Q9 多机 | 自建 WS + Node + 配对 | **v1 复用 DSH 的 `ssh/*` 系列**（远程 fs、子进程、沙箱）；自建 Node 后置 | 注意 DSH ssh **只支持 POSIX 远端**，Windows 作为被控机要等自建 Node |
| Q11 远程浏览器 | M4 自建三档 | **复用 DSH `browser-use` / `computer-use` 包** | 先能用，再谈三档 |
| Q12 办公 | 自写 docx/xlsx/pptx 技能 | **复用 DSH `document`、`deliverables` 包 + SKILL.md 技能** | 同上 |
| Q5 合规 | 找法务出书面意见 | **对外口径只写“使用你自己的 API Key / 本机已登录的官方 CLI”**；不做订阅代理，不用 Claude Code 品牌；有收入后再找法务 | 单人没有法务预算，用最保守口径规避 |
| Q13/Q14 品牌与形象 | 外部检索 + 画师买断 | **自己做商标/域名检索；形象 MVP 用参数化 SVG（AI 出概念、自己描）**，画师和 Rive 等有用户再说 | 预算 |

**Rust 怎么办**：v1 不写 Rust。DSH 是 TypeScript，AI 编程工具写 TS 同样熟练。Rust 留给 M4 以后两个确有收益的地方：①跨平台 Node 守护进程（补 Windows 被控机）；②有用户后若要做轻量 Tauri 壳。

## 2. 依据：DSH 已有什么，缺什么（2026-11-06 本地读码，commit `fcc0ad4`，MIT）

### 2.1 已有（直接复用）

| 用户诉求 | DSH 现成包（`repos/deepseek-harness/packages/...`） |
|---|---|
| 子 agent 有状态，可 fork、可插话 | `subagent/subagent`（委派中枢）、`subagent-fork-in-process`、`subagent-spawn-in-process`（本地子 Session **可持续对话**）、`tool-subagent-control`（按名字发消息、打断、等待收件箱）；`core/agent-loop` 中有 steer |
| 会话日志与持久化 | `session/*`（追加式日志、JSONL 持久化、checkpoint 策略、投影） |
| 定时任务 | `schedule/schedule`（重启后保留，补跑最近一次错过的执行） |
| PR / webhook 事件 | `experimental/webhook`、`experimental/webhook-github`、`experimental/forge-github`；`dsh-superagent-prototype` 的 `github-watch`、`feishu-watch` |
| 主 agent 只做分发（SuperAgent） | `dsh-superagent-prototype` 本身就是 DSH bundle：Source/Trigger/Thread/Ticket 模型，主 Session 与 Worker preset 分离（见其 `cordis.patch.yml`） |
| 接 Claude Code / Codex / ACP | `subagent-claude-code`（Agent SDK 0.3.263）、`subagent-codex`（`@openai/codex@0.153.4` app-server）、`subagent-acp` |
| 多机 | `ssh/*`（POSIX 远端） |
| 远程浏览器 / 电脑操作 | `browser-use`、`computer-use` |
| 办公产物 | `document`、`deliverables`、`skill` |
| 多端 | `apps/desktop`（Electron，已有 Windows 签名配置）、`apps/web`、`apps/cli` |
| 扩展机制 | 插件 + bundle（`cordis.patch.yml` 插入插件与 preset）+ `dsh.client.inject` 注入前端模块 |

### 2.2 缺口：DSH 里的外部编程 Agent 是“一次性”的

各包 README 的 *Known Limitations* 原文要点：

- `subagent`：**External children execute once**。ACP、Codex、Claude Code 没有本地子 Session，不接受后续输入。
- `subagent-codex`、`subagent-claude-code`：每次运行都是一个新进程、新 thread、新 turn，**没有 continuation、resume、进度流**。**没有人工审批通道**（权限请求一律拒绝）。只回传最终答案文本。
- `subagent-acp`：每次运行一个新进程；权限请求自动回答，用户看不到。DSH 自己的 Dev Note 把“可续接的 ACP 子 agent”列为未来工作。

**这正是我们的产品核心**：让 Claude Code、Codex 成为**有状态、可插话、可分支、审批可见**的子 Bot。研究文档 03 已查明底层协议都支持：Codex app-server 有 `thread/fork`、`turn/steer`、`turn/interrupt`；Claude Agent SDK 有 resume、`forkSession`、interrupt、`canUseTool`；ACP 有 `session/load` 和 `_session/steering`。所以单人主线工作量集中在这里，而不是重写内核。

## 3. 单人版架构

```
┌──────────── DSH Desktop(Electron) / Web UI ─────────────┐
│  muster-ui（client inject）：花名册+头像状态、审批卡、    │
│  子 Bot 时间线、分支列表、事件中心                         │
└──────────────────────────┬──────────────────────────────┘
                           │ DSH host
┌──────────────────────────┴──────────────────────────────┐
│ muster bundle（cordis.patch.yml）                         │
│  ├ muster-router     主 Bot preset：只有 dispatch/reply/   │
│  │                   ask_user 工具（借鉴 superagent 原型） │
│  ├ muster-codex      有状态 Codex 子 Bot（app-server 常驻）│
│  ├ muster-claude     有状态 Claude 子 Bot（Agent SDK）     │
│  ├ muster-acp        可续接 ACP 子 Bot（OpenCode/Goose）   │
│  ├ muster-approval   外部 Agent 权限请求 → DSH 交互/审批卡 │
│  ├ muster-worktree   每个子 Bot 一个 git worktree + turn 快照│
│  └ muster-events     把 schedule / webhook-github / 子 Bot │
│                      回调统一成事件并路由到 Thread         │
├──────────────────────────────────────────────────────────┤
│ DSH 现成：session 日志·schedule·subagent·ssh·browser-use· │
│ document·skill·mcp·sandbox                                │
└──────────────────────────────────────────────────────────┘
```

原则：
1. **不 fork DSH 主干**。pin 一个 commit/npm 版本，所有东西写成插件和 bundle；升级时只改适配层。
2. 能贡献上游就贡献（例如“可续接 ACP 子 agent”），减少自己长期维护的代码。
3. 外部 Agent 的会话以它自己为准，Muster 只存引用 + 摘要镜像（沿用 05 的默认决定）。

## 4. 单人路线图（估算，AI 辅助编码；按每周约 40 小时计）

> 周数是估算，不是承诺。每个阶段末尾自测一遍验收项，未过不进入下一阶段。

| 阶段 | 周 | 交付 | 验收 |
|---|---|---|---|
| **M0 上手与验证** | W1–W2 | 跑通 DSH 源码构建与桌面端；读懂 Cordis 插件、bundle 和 `dsh-superagent-prototype`；写第一个空插件并注入一个前端面板；实测 Codex app-server 的 steer/fork、Claude Agent SDK 的 resume/fork；测 Web UI 在手机 + Tailscale 下的可用性 | ①自定义插件能被 bundle 加载；②两个 spike 脚本在命令行中走通插话和分支；③写出一页“DSH 扩展点结果单” |
| **M1 有状态外部 Bot** | W3–W6 | `muster-codex`、`muster-claude`（常驻进程、续接、steer、interrupt、fork）；`muster-approval`（权限请求进 DSH 审批交互）；`muster-worktree` | 主会话能并行派 2 个任务给 Codex 和 Claude，中途插话、打断、从某一步分支，审批卡可批可拒；连续 10 次跑通 |
| **M2 主 Bot 与事件** | W7–W9 | `muster-router` preset；`muster-events` 接 schedule、webhook-github、子 Bot 完成回调；外部触发默认 observe | 一个 PR 事件或 cron 能自动唤起子 Bot，同一事件重复投递只触发一次；主 Bot 不直接执行命令 |
| **M3 界面与形象，内测** | W10–W12 | `muster-ui`：花名册、L0 参数化头像（7 种状态）、子 Bot 时间线、事件中心；引导流程；Windows 安装包；10 位左右种子用户 | 新用户 10 分钟内完成首次并行派发；“5 秒测试”能看出谁在干活、谁在等我 |
| **M4 扩展** | W13 起，按反馈排序 | 第二台电脑（POSIX 走 DSH ssh；Windows 被控机要自建 Node，可用 Rust）；远程浏览器（DSH browser-use）；办公技能；`muster-acp`；Rive 动画形象 | 按用户反馈定 |

和 05 的 6 周极限版相比，这个版本保住了“事件驱动”卖点，代价是多机与浏览器后移。原因是 DSH 已提供 schedule 和 webhook，事件这一块成本低。

## 5. 用 Claude Code 等工具单人开发的工作方式

- **先规格后代码**：每个插件先写 1 页规格（接口、事件、验收用例），放 `docs/specs/`，再让编程 Agent 实现。
- **录制回放夹具**：把 Codex 和 Claude 的真实协议流录成 JSONL，契约测试用回放跑，不必每次烧 token。
- **项目 `CLAUDE.md` / `AGENTS.md`**：写清“不改 DSH 主干、只写插件”“pin 版本”“每个插件必须带测试”。DSH 仓库自己就有 `AGENTS.md`，可以参考。
- **并行**：用 worktree 让多个编程 Agent 同时做互不相干的插件。这本身也是产品的 S1 场景，自己就是第一个用户。

## 6. 单人版主要风险

| 风险 | 对策 |
|---|---|
| DSH 处于 developer preview，会有破坏性变更 | pin 版本；适配层集中在少数文件；跟踪上游 release；必要时向上游提 PR |
| Cordis 插件范式学习曲线陡 | M0 留两周专门读源码、写空插件；对照 `dsh-superagent-prototype` 学 |
| Electron 体积与“轻量”诉求冲突 | v1 明确接受；UI 只依赖 DSH 协议，日后换 Tauri 壳 |
| Codex / Claude SDK 运行时体积大（DSH 文档：约 114 MB / 92 MB 打包体积） | 首次使用时按需下载，不随安装包分发 |
| DSH ssh 只支持 POSIX 远端 | Windows 被控机放到 M4，自建 Node |
| 品牌：DSH 是注册商标 | 产品名不用“DeepSeek Harness”，可写“built on DeepSeek Harness”（其 `BRAND_GUIDELINES.md` 允许） |
| 一个人范围蔓延 | 每加一项必须砍掉一项同量级的；M3 之前不做多机、浏览器、办公 |
