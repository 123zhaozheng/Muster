# 10 · 二期开发计划（2026-11-06）

一期做出了能跑的纵向切片，用户反馈：**页面不够饱满、偏窄、头像不会动、侧栏不能收起、点左上角 Logo 回不到首页、设置里不能配模型、只能配 Claude Code / Codex 当子 Agent**。二期要做三件事：

1. **UI 大整改**：精致、饱满、会动，UX 合理。
2. **接入真实模型**：用户在界面里自己配置，基于 pi-ai 原生的模型和 provider 体系。
3. **原生子 Agent**：用户可以自建内置成员，自定义人设、模型和工具，跑在 pi-durable 上。

## 一、模型配置：pi 原生支持什么（调研结论）

依据：`repos/pi-mono/packages/ai/README.md`，以及我们已安装的 `@earendil-works/pi-ai@1.5.0`。

- **Provider 是 pi-ai 的运行单元**：它自带模型目录、鉴权方式和流式实现。`createModels()` 得到一个 `Models` 集合，用 `models.setProvider(p)` 注册 provider，用 `models.getModels(providerId)` 查模型，用 `models.stream(model, context)` 调用。
- **内置 provider 有 35+ 个**，每个都有工厂函数 `@earendil-works/pi-ai/providers/<id>`；`builtinModels()` 和 `getBuiltinProviders()` 能一次性拿到全部。
  - 国内：DeepSeek、Moonshot（含 China）、MiniMax（含 China）、ZAI/智谱（含 China）、Qwen Token Plan（含 China）、Xiaomi MiMo。
  - 国际：OpenAI、Anthropic、Google、xAI、Mistral、Groq。
  - 聚合：OpenRouter、Vercel AI Gateway、Together、Fireworks。
  - 其他：Amazon Bedrock、Vertex 等。
- **鉴权**：provider 自己解析 key，有两个来源。一是 `CredentialStore`（接口为 `read/list/modify/delete`，按 providerId 存，存了就优先用），二是环境变量（如 `DEEPSEEK_API_KEY`）。**我们实现一个基于文件的 CredentialStore**，路径 `dataDir/credentials.json`，key 永远不下发给客户端。
- **自定义端点**：用 `createProvider({ id, name, baseUrl, auth, models, api })`，`api` 取 `openAICompletionsApi()` 或 Anthropic messages API，可覆盖任意 OpenAI 兼容服务（Ollama、vLLM、LM Studio、公司网关、各类中转）。兼容性差异用 model 上的 `compat` 字段处理。
- **pi-durable 直接复用这套机制**：`Harness.open(storage, { models, ... })`，每个 conversation 自带 `agent.model = { provider, modelId }`。所以**同一个 `Models` 实例同时服务 Pip 的路由和所有原生子 Agent**。

结论：**不需要自己造模型层**。我们的 `ModelService`（`packages/daemon/src/models/service.ts`）只做四件事：

1. 管理用户配置，文件 `dataDir/models.json`。
2. 实现 CredentialStore。
3. 根据配置构建 pi-ai 的 `Models`。
4. 提供 `model.*` 系列 RPC。

## 三、UI 设计规范（全体前端遵守）

**参考**：`design/mockups/*.png`（这是饱满度的目标）；一期截图见 `design/screenshots/*.png`（这是现状，问题在于空、窄、静）。气质上要像 Lovable、Meta Muse 和 Linear 的结合：温暖、精致，信息密度适中。

**布局**
- 外壳由三部分组成：可收起的左侧栏、顶部条、内容区。侧栏展开时宽 248px，收起时是 72px 的图标栏；按 `Ctrl/⌘+B` 切换，状态存 localStorage。窄于 1200px 时自动收起。**点击 Logo 回到主线 `/`**。
- 顶部条高 56px，放面包屑或页面标题、全局搜索框（`Ctrl/⌘+K` 打开命令面板：跳转页面、找 Bot、找任务）、"需要你"铃铛（未读数，点开浮层列出待审批，可直接批）、连接状态点，以及演示模式标签。
- 内容区**用满宽度**：主区自适应，右栏固定 340~380px，需要时才出现；内容最大宽度 1680px，居中。页面边距 32px，卡片间距 20~24px。窄屏下右栏下沉到主区下方。
- 每个页面的结构：`PageHeader`（大标题 + 一句副标题 + 右侧主操作按钮）→ 概览区（统计卡或 Hero）→ 主体。**不允许出现大片空白**；数据少时用插画式空状态（大号 Pebble + 引导文案 + 主操作按钮）。

**视觉**
- 沿用一期的 token：暖白底、珊瑚橙 `#FF6B4A`、薰衣草紫 `#8B7CF6`、薄荷绿，可以新增。卡片圆角 20~24px，阴影用三层柔和阴影，hover 时上浮 2px 并加深阴影。
- 背景要有层次：页面顶部有柔和的渐变光晕，卡片用半透明毛玻璃，分区有浅色底。
- 字体层级：页面标题 28/34 半粗、区块标题 17 半粗、正文 14/22、辅助文字 12。数字用 tabular-nums。
- 状态色统一：工作中=薄荷、思考=薰衣草、等你审批=琥珀、出错=红、完成=薄荷、空闲或睡眠=灰。

**动效**（用已安装的 `motion`，尊重 `prefers-reduced-motion`）
- **吉祥物 Pebble 必须一直是活的**：
  - 空闲：呼吸起伏（scale 1→1.03），每 3~5s 随机眨眼，小芽轻轻摆动。
  - 思考：眼珠左右看，头顶出现 "…" 气泡。
  - 工作中：轻快上下弹跳，配专注眼和速度线。
  - 等你审批：举手挥动，配感叹号脉冲。
  - 已完成：弯月笑眼，闪光粒子出现一次后定格微笑。
  - 出错：螺旋晕眩眼，轻微抖动。
  - 睡眠：闭眼，Zzz 上浮。
  - 状态切换时有 200ms 的 squash & stretch 过渡；hover 时眼睛跟随鼠标或开心一下；点击时弹一下。
  - 尺寸 16~200px 都要好看；同屏 30 个时不能卡（优先用 CSS 动画；在列表里的小头像可以降级，只保留眨眼和呼吸）。
- 页面切换淡入加 8px 上移；列表项进入时依次出现；数字变化有滚动动画；进度条平滑过渡；流式文字带光标。
- 时长：微交互 120~200ms，过渡 240~320ms，统一 easing `[0.22, 1, 0.36, 1]`。

**交互**：所有可点元素都有 hover、active、focus-visible 状态；危险操作需要二次确认；异步操作要有 loading 态，结果用 Toast 反馈；表单要有校验提示；常用操作有快捷键并在 UI 上标出。
