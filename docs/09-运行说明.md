# 09 · 运行说明

适用于 2026-11-06 的纵向切片。环境：Node >= 22.19、pnpm 11（经 `scripts/pnpm-locked.mjs` 串行调用）、Windows 11 / Git Bash 已验证。

## 1. 启动方式

在仓库根目录 `D:\code\xuqiu` 执行：

| 命令 | 作用 |
|---|---|
| `pnpm web` | 只起前端（Vite，`http://localhost:5173`）。默认连 `ws://127.0.0.1:7788/ws`。 |
| `pnpm daemon` | 只起后台 musterd（`tsx watch`，默认端口 7788，数据在 `~/.muster`，未设 `MUSTER_TOKEN` 时不鉴权，仅限本机回环）。 |
| `pnpm desktop` | 构建桌面壳 -> 若 5173 没有服务则自动拉起 Vite -> 启动 Electron；Electron 自己拉起 daemon 并带 `?daemon=...&token=...` 加载界面。退出时一并清理 Vite 与 daemon。 |

常见组合：

- **纯前端演示（mock）**：`pnpm web`，浏览器打开 `http://localhost:5173/?mock=1`。不需要 daemon，数据由 `apps/web/src/lib/mockClient.ts` 模拟。也可在浏览器里设 `localStorage muster.mock=1`（设置页有开关）。
- **前端 + 真实 daemon（fake 引擎）**：一个终端 `MUSTER_FAKE=1 pnpm daemon`，另一个终端 `pnpm web`，打开 `http://localhost:5173/`（无 `mock` 参数）。主线发“交给小码修 xx，交给阿克写 yy”会出现两张派发卡，子 Bot 由脚本化 fake 驱动工作。
- **桌面端演示**：`MUSTER_DESKTOP_FAKE=1 pnpm desktop`。建议同时设 `MUSTER_USER_DATA=<临时目录>`，避免污染 `%APPDATA%/Muster`。
- **桌面端加载已构建界面**（不依赖 Vite）：先 `pnpm -F @muster/web build`，再 `MUSTER_WEB_URL=dist MUSTER_DESKTOP_FAKE=1 pnpm desktop`。

### 环境变量

| 变量 | 所属 | 含义 |
|---|---|---|
| `MUSTER_FAKE=1` | daemon | 三种引擎（codex/claude/native）全部用 fake 驱动。 |
| `MUSTER_FAKE_SPEED=fast` | daemon | fake 驱动每步约 20ms（默认 300~800ms），测试用。 |
| `MUSTER_PORT` / `MUSTER_TOKEN` / `MUSTER_DATA_DIR` | daemon | 端口、鉴权 token、数据目录。 |
| `MUSTER_DESKTOP_FAKE=1` | desktop | 壳启动 daemon 时设 `MUSTER_FAKE=1`。 |
| `MUSTER_WEB_URL` | desktop | 界面地址，默认 `http://localhost:5173`；设为 `dist` 则加载 `apps/web/dist`。 |
| `MUSTER_USER_DATA` | desktop | 覆盖 Electron userData（默认 `%APPDATA%/Muster`）。daemon 数据在其下 `data/`，日志在 `logs/daemon.log`。 |
| `MUSTER_DESKTOP_EXIT_AFTER_MS` | desktop | N 毫秒后走正常退出流程（冒烟用）。 |
| `MUSTER_DESKTOP_SCREENSHOT` | desktop | PNG 路径。界面加载后截图，并在同名 `.json` 写出页面状态（是否 mock、页面文本等）。 |
| `MUSTER_DESKTOP_SMOKE_MESSAGE` | desktop | 配合上一项：截图前先在主线发这条消息。 |
| `MUSTER_DESKTOP_SCREENSHOT_DELAY_MS` | desktop | 发送后等多久再截图，默认 6000。 |
| `MUSTER_DESKTOP_SMOKE_CLOSE=1` | desktop | 截图后模拟点关闭，把窗口是否仅隐藏写入 `.json` 的 `afterClose`。 |
| `MUSTER_ROUTER_LLM=1` + `MUSTER_ROUTER_BASE_URL/API_KEY/MODEL` | daemon | 开启 Pip 的 LLM 路由（OpenAI 兼容 `/chat/completions`），默认关闭，走规则路由。 |
| `MUSTER_NATIVE_MODEL` + `MUSTER_NATIVE_BASE_URL`（可选 `MUSTER_NATIVE_API_KEY`），或 `OPENAI_API_KEY` | daemon | 原生 Bot 的模型配置；缺失时 `app.ts` 回退到 fake。 |
| `MUSTER_CODEX_TRACE=<文件>` | daemon | 把 Codex app-server 的 JSON-RPC 收发追加到该文件，调试用。 |

示例（复现 `design/screenshots/desktop-home.png`）：

```
MUSTER_USER_DATA=D:/tmp/muster-ud MUSTER_DESKTOP_FAKE=1 MUSTER_WEB_URL=dist \
MUSTER_DESKTOP_SCREENSHOT=D:/code/xuqiu/design/screenshots/desktop-home.png \
MUSTER_DESKTOP_SMOKE_MESSAGE="交给小码修支付回调，交给阿克写退款接口" \
MUSTER_DESKTOP_EXIT_AFTER_MS=30000 pnpm desktop
```

## 2. 真实 Codex / Claude 的前提

不设 `MUSTER_FAKE` 时，daemon 使用真实驱动：

- **Codex**：本机 PATH 上有 `codex`（已验证 0.166.0），并且已登录（`codex login`）。驱动通过子进程 `codex app-server` 通信。登录令牌过期时，turn 会以 `failed` 结束并带上原因。
- **Claude Code**：本机 PATH 上有 `claude`（已验证 2.1.314），并已登录。驱动直接 spawn `claude` 的 stream-json 模式，不读取凭据。注意用户本机的 skills / MCP / CLAUDE.md 会被继承，一次调用可能较贵。
- **GitHub 触发器**：需要本机装有并登录 `gh`。
- 到“技能”页或团队页的“添加成员”可以看到各 Agent 的检测结果（`bot.detectAgents`）。

## 3. 目录结构

```
apps/
  web/        React + Vite 前端（pages/ 各页面，components/，lib/hub.ts 数据层，lib/mockClient.ts 离线 mock）
  desktop/    Electron 壳（src/main.ts 主进程，src/daemon.ts daemon 生命周期，src/smoke.ts 联调截图，scripts/dev.mjs）
packages/
  protocol/   线协议、共用 reducer、client 抽象、fixtures（契约，已冻结）
  daemon/     musterd：core/（Hub 与契约）、server/（WS）、persist/（日志）、handlers/、
              drivers/{fake,codex,claude,native}/、orchestrator/、router/、triggers/
  ui/         设计 token、Pebble 吉祥物、通用组件（含 UiGallery）
design/       概念稿 mockups/ 与联调截图 screenshots/
docs/         设计与计划文档
```

数据落点（daemon）：`<dataDir>/muster.db`（Hub 快照，SQLite WAL）、`orchestrator.json`（任务到引擎会话的映射）、`triggers-seen.json`（触发器状态）、`native.db`（原生 Bot）。

## 5. 已知限制

- **桌面壳**：只有开发模式路径。没有 electron-builder 配置，daemon 不随壳打包；daemon 用 PATH 上的 `node`（需 22+）加 `--import tsx` 运行源码。Windows 上停止 daemon 是 `taskkill /T /F` 强杀，没有优雅停止，日志里会看到 `code=1`，属正常；Hub 数据靠节流写入（最多约 500ms）加关闭时同步落盘，强杀可能丢最后约 0.5 秒的推送。
- **mock 模式**：设备上下线不模拟；审批只有“运行 pnpm install”一种；Pip 对无法识别的消息给固定回复。
- **fake 驱动**：默认 25% 概率让子 Bot 请求审批；要稳定触发审批，在消息里写“安装依赖”。
- **真实驱动**：Codex 的文本流、工具、审批、fork 在真机上未完整验证（令牌过期）；Claude 的审批、steer、queue、按轮 fork 仅假进程验证。
- **Pip 路由**为规则启发式；LLM 路由只用假 fetch 测过。
- **触发器**：GitHub 用 `gh` 轮询 Events API，有分钟级延迟；设备事件来自 Hub 的 `device.updated`；设备配对只有配对码占位，不做跨机配对。
- **前端**：首次引导页的名称/形象只存 localStorage，不会改 daemon 里的 Bot；不会自动跳转到 `/onboarding`；安全等级只存储不生效；右栏在窗口宽度小于 1024px 时隐藏。
- **构建产物**：`apps/web/dist/`、`apps/desktop/dist/` 以及 `muster.db-wal`、`muster.db-shm` 当前不在 `.gitignore` 中，提交前需补上。
