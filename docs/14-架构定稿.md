## 0. 一句话

**Muster = 一个常驻的管家 Pip + 一组成员。你只跟 Pip 说话；Pip 不干活，只管“工单”；成员在指定设备、指定目录里真干活。**

只有 4 个核心概念，其它都挂在它们下面：

| 概念 | 是什么 | 现在对应 |
|---|---|---|
| **Pip** | 常驻管家会话：听你说、开/挂/停工单、汇报、问你、记东西 | router（只会路由） |
| **成员 Member** | 能干活的 agent：原生成员 / Codex / Claude Code / 其它 ACP agent | bot |
| **工单 Ticket** | 一件事。含 1 个或多个“尝试 Attempt”（谁、在哪台设备、哪个目录、哪个会话） | task + branch |
| **设备 Device** | 能跑成员的机器：本机 / SSH 主机（以后：muster-node） | 只有写死的“本机” |

“分支”这个概念取消：多方案 = 一张工单里的多个尝试；对话 fork 降级为尝试里的“从这一步重来”。

## 1. Pip 的 harness

### 1.1 结构（跑在 pi-durable 上，不换内核）
```
你 / 成员汇报 / 日程触发
        │  (都变成带 id 的收件箱消息，重启不重复)
        ▼
  [收件箱适配器] ──规则直通──▶ 点名、停止、审批（不过模型）
        │
        ▼
  [Pip 会话 pip.db]  ← 系统提示：身份 / 路由规则 / 输出规则 / 成员清单 / 常驻记忆
        │  工具调用
        ▼
  [工单服务] ──▶ [编排器 + 驱动] ──▶ 成员在设备上干活
        ▲                                  │
        └──── [汇报生成器] ◀── 完成/卡住/要审批 ┘
        │
        ▼
  [发件箱]：先落库再推 UI
```
- 你说话时 Pip 正忙 → 插进当前回合；汇报/触发 → 排队合批。
- 中止 Pip 不会停掉成员。
- Pip 用快、便宜、工具调用稳的模型，思考档低。

### 1.2 Pip 的工具（11 个，Pip **不碰文件、不跑命令**）
| 工具 | 干什么 |
|---|---|
| `route` | 一次 1–10 个决定：**新建 / 挂到已有工单 / 停止 / 忽略**；新建时原话转交 + ≤30 字备注 + 设备/目录/方案数 |
| `read` | 读工单、汇报、成员、设备、日程、记忆（按 id 逐跳） |
| `say` | 对你说话的唯一出口（默认安静，只在 有结果 / 要你决定 / 做不下去 时开口） |
| `ask_user` | 一次只问一个问题，带选项 |
| `ticket_note` | 给工单补充事实 |
| `ticket_retry` | 换成员/换会话重试 |
| `attempt_add` | 给工单加一个并行方案 |
| `schedule` | 建日程：观察 / 先问 / 自动 |
| `memory_search` / `memory_propose` | 查记忆；提议记忆（你确认才生效） |
| `web_search` | 只读搜索（已确认开放） |

## 2. 成员

### 2.1 统一模型
```
Member {
  id, name, avatar, persona, skills
  runtime:
    native   → model, effort, tools, mcp
    external → agent(codex|claude|acp:*), 接入方式, modelMode(自己的登录|Muster 模型), model
  placement: 允许的设备、默认设备、常用仓库
  policy:    审批策略、最大并发、单工单预算
}
```
steer / fork / 中断 / 审批 / 续跑 等能力由驱动上报，不让你填。

### 2.2 Codex / Claude Code：必须装在跑它的那台设备上 → 要“激活”
每台设备 × 每个 agent 一张状态卡：

**未安装 → [一键安装] → 未登录 → [登录] 或 [改用 Muster 模型] → 已就绪**

| | 检测 | 安装 | 登录 |
|---|---|---|---|
| Claude Code | `claude --version` + `claude auth status`（JSON，0/1） | 官方安装脚本 / winget / npm | 本机 `claude auth login`；远端用 `claude setup-token` 生成的令牌，每次以环境变量传入，不落盘 |
| Codex | `codex --version` + `codex login status` | `npm i -g @openai/codex` | 本机 `codex login`；远端 `codex login --device-auth` |

- **默认用它们自己的登录**（订阅额度最划算）。
- **可选“用 Muster 的模型”**：Claude 用独立 `CLAUDE_CONFIG_DIR` + `ANTHROPIC_BASE_URL/AUTH_TOKEN/MODEL`；Codex 用独立 `CODEX_HOME` + 自定义 provider（只支持 Responses 接口的模型）。不污染你自己的配置。
- 继续直接调本机 CLI（`claude` stream-json / `codex app-server`），不用 Claude Agent SDK（它的条款不允许第三方产品用订阅登录）。
- 其它 agent（Gemini CLI、OpenCode…）走通用 **ACP** 驱动。

## 3. 工单（取代“分支”）
- 字段：发起人、授权范围、订阅（PR 评论 / CI / 你的追问自动送达）、状态机（排队 / 进行中 / 等你回答 / 等你审阅 / 卡住 / 失败 / 完成）。
- **尝试 Attempt** = 成员 + 设备 + 工作区（仓库 + 目录 + 隔离方式：worktree / 原地 / 临时）+ 会话。
- **多方案**：一张工单开 2–3 个尝试并行 → 自动跑验证命令 → Pip 给对比 → **采用 = 真的合并回你的分支或开 PR**，其余清理。
- 修掉现在“任务永远跑在空目录”的问题。

## 4. 记忆
- 来源：你说“记住…”（直接生效）；工单完成时 Pip 提取候选、成员提议（**都要你点一下确认**）。
- 存储：`~/.muster/mind/*.md`，git 版本化可回滚。
- 使用：派单时只放摘要 + 指针，成员需要再展开。

## 5. 设备
- **一期：SSH**（设备 = `~/.ssh/config` 主机）；Codex/Claude 通过 ssh 在远端起；原生成员经 SSH 执行，远端零安装。网络用 Tailscale。
- **二期：muster-node**（每台设备主动连回，配对码 + 设备密钥），解决 NAT、无 sshd 的 Windows、断线不丢任务。

## 6. UI（对标 ChatGPT / Claude 网页版；LobeHub 只借思路，不抄代码——它的许可不允许二次分发衍生品）

**原则：默认收起，点开才详细；一行能说清的不写一段；不放页面大标题。**

### 6.1 主线页
- **头部 44px**：左边只有会话名 `Pip ⌄`（14px），进入成员对话时变成面包屑 `主线 / 小码 · 修登录`；右边最多 3 个图标：进行中数量、右栏开关、更多。**删掉“主线”大标题。**
- **“此刻”右栏默认关闭**，换成头部的一个状态胶囊（`2 需要你 · 3 进行中`），点开才出 340px 面板（可拖宽、记住状态）。面板里是**行**不是段落：图标 + 一行文字 + 右侧数字，每组最多 3 行 + “查看全部”，没数据的组不显示。
- **消息**：你的消息右对齐浅底气泡、无头像；Pip/成员无气泡，24px 头像 + 来源标签；时间和操作按钮悬停才出现。
- **思考**：流式时 `思考中 · 8s`（灰色、轻动效）；完成折叠为 `已思考 12s ›`，点开看全文。
- **工具调用**：每次一行 `运行 pnpm test · 12s`；连续调用合并为 `共 8 次调用 · 1 次失败 · 34s ›`；一轮结束后整轮过程折叠为 `已处理 5 步 · 2m10s ›`，最终回答始终可见。
- **派发**：一个任务组卡片，每个工单一行（状态、成员头像、标题、用时），点开才看摘要。成员的完整对话不灌进主线。
- **审批**：停靠在输入框上方（`批准一次 / 拒绝`，“本会话都允许”放在 ⋯ 里），不弹窗。
- **空状态**：内容贴近输入框，最多 4 个建议，点了只填入不发送。

### 6.2 中文排版
正文 15px / 行高 1.7 / 不加字间距；行长 ≤ 40 字；中英文之间留空隙；不整段加粗；状态标签 ≤ 12 字；层级靠三档灰 + 间距，不靠边框。

### 6.3 保留
动效（Pip 与图标，可在设置里关）、左右栏拖拽调宽、单一强调色 `#5976D9`、不造假数据。

### 6.4 要删要并的
- “分支”页 → 并入工单详情的“方案”页签。
- “此刻”常驻右栏 → 头部状态胶囊 + 按需面板。
- 工作台 → 改名“工单详情”，与主线同一套消息/思考/工具组件。
