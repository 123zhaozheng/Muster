# 11 接入真实模型

Muster 的两处用到大模型：

- **Pip（主 Bot）**：理解你在主线说的话，决定派给谁、闲聊答疑。用「路由模型」。
- **原生成员**：跑在内置 Agent 框架（pi-durable）上，用「原生成员默认模型」，或成员自己指定的模型。

外部编程 Agent（Claude Code、Codex）的模型由它们自己管，这里不配置。

没有配置模型时一切照常启动：Pip 退回关键字规则分发（主线会提示一次「Pip 还没配置模型，暂按规则分发（设置 → 模型）」），原生成员会回一条中文提示让你去配置。

## 一、启动

```bash
pnpm daemon     # 后台，默认 ws://127.0.0.1:7788，数据在 ~/.muster
pnpm web        # 前端
```

不要带 `MUSTER_FAKE=1`（那是演示用的假驱动）。更多说明见 `docs/09-运行说明.md`。

## 二、在界面里配置（推荐）

入口：左侧栏「设置」→「模型」（命令面板里也有「打开设置 · 模型」）。首次进入 Muster 的引导页第三步也可以配置一个。

### 1. 用内置服务商（填 Key）

1. 「添加模型服务」→ 选「从内置目录选」。
2. 在目录里选服务商（DeepSeek、Moonshot、MiniMax、智谱、通义千问等国内服务商排在最前，其后是国际、聚合、云厂商、本地）。
3. 填 API Key。该服务商在环境变量里已有 Key，或属于「本地」分组时可以不填。
4. 可选：勾选要启用的模型（不勾 = 全部可用）；填 Base URL 可覆盖官方地址（走代理或中转时用）。
5. 点「测试连接」。它会先保存配置，再发一条很小的请求（只回复 OK）。成功会显示延迟和回复。

### 2. 自定义兼容端点

适用于任何 OpenAI 兼容或 Anthropic 兼容的地址（公司网关、中转站、Ollama、vLLM、LM Studio 等）。

1. 「添加模型服务」→ 选「自定义兼容服务」。
2. 接口类型选 OpenAI 兼容或 Anthropic 兼容。
3. 名称随意；Base URL 通常以 `/v1` 结尾，例如 `http://localhost:11434/v1`。
4. 模型 ID：回车或逗号确认，可以添加多个，必须与服务端的模型名完全一致。
5. API Key：本地服务可以留空（内部会用占位 Key，Ollama 之类不校验）。
6. 默认的上下文窗口为 128000、单次输出上限为 8192，OpenAI 兼容端点使用保守的兼容设置（不发 store、developer 角色、reasoning_effort）。

### 3. 设默认模型

页面顶部「默认模型」卡有两项：

- **Pip 路由模型**：Pip 用它理解和分发。不设则只用规则路由。
- **原生成员默认模型**：没有单独指定模型的原生成员使用它。

选择后即保存，改完马上对已有会话的下一条消息生效，不用重启。每项旁边有「测试」按钮。

### 4. 给成员指定模型

「团队」页 → 成员卡片右上角「编辑」：

- 原生成员：在「模型」下拉里选一个，或选「使用默认模型」。
- Pip：「路由模型」，不选则跟随设置里的路由默认。
- 新建成员：「新建成员」→ 原生成员（推荐）→ 外观 → 能力（人设、模型、工具分组、技能）→ 确认。

注意：成员的模型在任务启动时确定。运行中的任务不会切换，改完模型后新开的任务才使用新模型。

### 5. 新建原生成员

1. 「团队」→「新建成员」→ 类型选「原生成员」。
2. 起名字（不能和现有成员重名），选形象和颜色。
3. 能力一步：可套用模板（研究员、办公助手、代码审查、翻译写作），或自己写人设；选模型；选工具分组。
4. 工具分组：`文件读取`（read / ls / grep）、`修改文件`（write / edit，需审批）、`运行命令`（bash，需审批）、`网页抓取`（web_fetch，需显式勾选）。默认是读取文件。
5. 技能标签会被 Pip 用来判断谁擅长什么。创建后在主线说「交给 XX …」或直接描述需求，Pip 会派给合适的人。

## 三、环境变量兜底

只有在界面里一个服务商都没配置时才生效，一旦配置了任何服务商就全部让位。这些隐式服务商在界面里只读，不能编辑或删除。

| 变量 | 作用 |
| --- | --- |
| `MUSTER_NATIVE_MODEL` + `MUSTER_NATIVE_BASE_URL`（+ `MUSTER_NATIVE_API_KEY`） | 原生成员的默认模型，走 OpenAI 兼容端点 |
| `MUSTER_NATIVE_MODEL` + `OPENAI_API_KEY`（不设 BASE_URL） | 使用内置 OpenAI 的该模型 |
| `MUSTER_ROUTER_LLM=1` + `MUSTER_ROUTER_BASE_URL` + `MUSTER_ROUTER_API_KEY` + `MUSTER_ROUTER_MODEL` | Pip 的路由模型（四项都要有） |
| 各服务商自己的 Key 变量，如 `DEEPSEEK_API_KEY`、`OPENAI_API_KEY`、`ANTHROPIC_API_KEY` | 该服务商作为隐式服务商出现，名称带「（环境变量）」 |

数据位置（`MUSTER_DATA_DIR`，默认 `~/.muster`）：

- `models.json`：服务商与默认模型设置，不含 Key。
- `credentials.json`：API Key。Windows 上仅当前用户可读，POSIX 上权限为 0600。Key 不会出现在任何推送、快照或其他文件里，也不会回显到界面（只显示「已设置」）。

删除服务商会同时删除它的 Key，并清掉默认模型里指向它的引用。

## 四、没有真实 Key 时本地跑通

```bash
node scripts/fake-openai.mjs --port 8787          # 可加 --key sk-xxx 要求鉴权
```

然后按上面「自定义兼容端点」填 Base URL `http://127.0.0.1:8787/v1`、模型 ID `fake-chat`、Key 任意。

- Pip：消息里点名成员，或含「调研 / 查一下」等词，会返回分发；其他是闲聊文字。
- 原生成员：返回一段中文回答；消息里含「读一下 xxx.md」会先演示一次 read 工具调用。

自动化版本是 `packages/daemon/src/e2e-real.test.ts`（`pnpm -F @muster/daemon test`）。

## 五、常见错误排查

| 现象 | 原因与处理 |
| --- | --- |
| 「API Key 无效或已过期（401）」 | Key 填错、过期或服务商不对。重新填写后再测试。 |
| 「没有权限访问该模型（403）」 | Key 没有访问该模型的权限，或账号/地区受限。 |
| 「模型 … 不存在（404）」 | 模型 ID 拼错，或 Base URL 少了 `/v1`、多了路径。对照服务商文档。 |
| 「请求被限流或额度不足（429）」 | 触发限流或余额用尽。稍后重试或充值。模型请求最多自动重试 2 次，401 不重试。 |
| 「连不上 baseUrl」或「请求超时」 | Base URL 写错、服务没启动、被代理或防火墙拦了。本地服务确认端口和 `curl <baseUrl>/models`。测试超时 30 秒。 |
| 「还没有 API Key」 | 内置服务商没填 Key。自定义本地服务不会出现这个（会用占位 Key）。 |
| 原生成员回复「还没有可用的模型」 | 没有配置任何服务商，或默认模型指向了已删除、已停用的服务商。到「设置 → 模型」重新选默认模型。 |
| Pip 提示「Pip 还没配置模型，暂按规则分发」 | 路由模型没设。设置「Pip 路由模型」。 |
| Pip 提示模型调用失败后按规则分发 | 路由模型请求出错（Key、网络、模型名）。到设置里点「测试」看具体原因。 |
| 推理型模型测试回复为空 | 测试只给 32 个输出 token，推理模型可能全用在思考上。只要没报错就算通过。 |
| 删除服务商后成员报「没有可用的模型」 | 成员的模型引用不会自动清理。编辑成员改回「使用默认模型」。 |
| 演示模式（`?mock=1`）里模型是预置的 | 演示数据不会连真实服务，要用真实模型请连接 daemon。 |

## 六、已知限制

- `model.test` 只能测已保存的服务商，所以「测试连接」会先保存。
- 用量与花费在每一轮结束时累计，不是流式实时；「本周花费」目前是启动以来的累计值。
- `web_fetch` 不需要审批，也不拦截内网地址；只在确实需要联网的成员上开启。
